# 문제 이해 및 설계 범위

- DAU : 5백만
	- 10% 사용자가 하루에 1 비디오를 업로드
- 일평균 30분
	- 하루 평균 5개 시청
- 다국어 지원
- 모든 비디오, 모든 해상도 지원
- 암호화
- 비디오 크기는 1GB
	- 평균 300MB
- 멀티플랫폼 (모바일, 앱, 웹브라우저, 스마트TV)

1GB당 0.02$라고 할 때,   

0.3GB x 5백만 x 0.02 x 5 비디오 = 150000$

### 스트리밍
프로토콜

### 비디오 트랜스코딩
= 인코딩
사용자의 비디오를 그대로 올려서 사용하면 너무 크다.
대역폭, 단말에 따라서 화질을 여러개 준비해야 하고, 여러 포맷으로 인코딩해 두어야 한다.

- 컨테이너 : 비디오 파일, 오디어, 메타데이터를 담는 바구니
	- .avi, .mov, .mp4 같은 확장자
- 코덱 : 비디오 화질은 보존하면서 파일 크기를 줄일 목적으로 고안된 압축 및 압축해제 알고리즘
	- H.264, VP9, HEVC 등등


## 유향 비순환 그래프 모델 (DAG)
![[Pasted image 20250921121532.png]]
수행할 작업을 손수 지정할 수 있어야 한다.
비디오는 3가지로 나뉜다. 비디오, 오디오, 메타데이터

![[Pasted image 20250921122146.png]]
- **전처리기**
	- 비디오 분할
	- DAG 생성
	- 데이터 캐시
- **DAG 스케줄러**
	- DAG를 분리하고, 작업 큐에 넣어 작업을 시킨다.
- **자원 관리자**
	- 작업 큐, 작업 서버 큐, 실행 큐, 작업 스케줄러
	- 작업 큐에서 꺼내서, 작업 서버 큐에 넣고, 서버가 실행할 때, 실행큐에 넣고, 끝나면 실행큐에서 뺌
- **DAG에서의 각 job 마다 서버를 구분하여 관리한다.**
	- 워터마크 서버, 인코딩 서버, 썸네일 서버 등등

## 최적화
- 비디오 병렬 업로드
	- 비디오를 여러 개의 GOP로 나눔 (GOP; 그냥 여러 프레임 그룹)
		- 1~100, 1~30, 30~60, 60~100
	- 분할한 걸 병렬로 업로드하면 빠르다.
	- 실패도 잘 컨트롤 가능
- 엣지 로케이션
	- 사용자 가까이 배치하기 위해서 CDN을 사용
- 모든 절차를 병렬화
	- 기존에는 다음 작업이 이전 작업에 종속적임![[Pasted image 20250921124933.png]]
	- 메시지 큐를 이용해서 개선 ![[Pasted image 20250921125002.png]]
- 안전성 최적화 : pre-signed url
	- 허가받은 사용자만 업로드 가능하게.
	- 서버에 요청하면 업로드 주소를 내려줌
- 안전성 최적화 : 비디오 보호
	- DRM: Apple FairPlay, Google Widevine, Microsoft PlayReady
	- AES 암호화
	- 워터마크
- 비용 최적화
	- 인기 비디오만 CDN에서 재생
	- 인기 비디오는 지역에 따라 다르다.
	- **CDN을 직접 구축하고, ISP와 제휴한다.**
- 오류 처리
	- 회복 가능 오류
	- 회복 불가능 오류
